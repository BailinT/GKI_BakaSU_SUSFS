## 四、上游同步规则

1. **何时看上游**：本仓出构建失败、或 coolzyd 仓 push 时间变化（`api.github.com/repos/coolzyd9107/GKI_BakaSU_SUSFS` 的 `pushed_at`）时核对；不追每周盲同步。
2. **同步方式**：手工对照移植（本仓已带 KPN/auto_release/署名等自有改动，不能直接 merge 覆盖）。coolzyd 新 commit → 看 diff → 判断是否影响本仓改过的文件 → 手工搬。
3. **BakaSU 上游跟进**：KSU 源码集成走 setup.sh 动态拉 main，管理器版本对齐看 `Baka-SU/BakaSU/releases`（当前 v4.2.0-rc3 线，内核 35205 / 管理器 35203 同线）。
4. **数据同步工作流**：每周一自动跑，只更新 `data/android*/`（GKI 官方版本矩阵），与上述依赖仓无关，失败不影响构建。
